## 2. 추가한 데이터와 화면 적용

기존 18개 일본 상품 모두 서로 다른 식사 구성으로 설정했습니다. 실제 조사 상품 6개에도 가상 정보는 presentationDemo 전용 영역에만 있으며 실제 여행사 정보로 표시하지 않습니다. 실제 meals 필드를 채우거나 기존 included/일정/가격/도보/휴식을 바꾸지 않았습니다.

| 가상 상품 예시 | 한식 | 현지식 | 자유식 | 가상 기온 |
| --- | ---: | ---: | ---: | --- |
| demo-01 유후인에서 느리게, 온천 쉼표 | 3회 | 4회 | 1회 | 후쿠오카 11월 10~18°C |
| demo-02 벳푸 온천과 작은 마을 산책 | 1회 | 5회 | 2회 | 후쿠오카 11월 10~18°C |
| demo-03 규슈의 맛, 여유로운 미식 여행 | 4회 | 2회 | 2회 | 후쿠오카 11월 10~18°C |

3일 상품은 총 7~8회, 4일 상품은 10~11회입니다. 가상 기온 예시는 오사카 2월 4~11°C, 후쿠오카 2월 5~12°C, 삿포로 2월 -7~-1°C, 오사카 11월 8~17°C, 삿포로 11월 0~8°C 등입니다. 전부 화면 시연용으로 만든 값이며 실제 통계·예보가 아닙니다.

카드: 한식/현지식 2종 요약 + 데모 예시 표시, 기온 + ‘데모 예시 기온 · 실제 예보 아님’.
비교·상세: 자유식 포함 전체 식사 구성과 출처 상태.
날짜 없는 상품: 가상 데이터의 2월을 시연 월로 명시하고 ‘여행 날짜 미정’을 함께 표시. 실제 출발 월을 알아낸 것으로 취급하지 않음.

## 3. 실제 식사 데이터 확인 결과

기존 일정표에는 호텔 조식·점심·저녁 식사라는 일반 표현만 있습니다. 한식/현지식/자유식별 확정 횟수는 없습니다. 이를 식사 유형 횟수로 추정하지 않았습니다. 실제 수치를 추가하려면 meals에 유형별 횟수, sourceUrl, checkedAt, evidence, confirmed 상태를 저장해야 합니다. 확인된 실제 meals는 발표용 가상 식사를 자동으로 대체합니다.

## 4. 날씨 API 연동과 우선순위

기존 Open-Meteo /api/weather 엔드포인트를 유지했습니다. 새로운 외부 API/키/과금 연결은 추가하지 않았습니다.

출발일과 방문 목록에 확인되는 지원 도시가 있고 여행 전체 기간이 최대 16일 예보 창 안에 있을 때만 자동 조회합니다. 같은 도시/날짜/일수 요청은 브라우저에서 5분간 재사용합니다. 실제 유효 기온이 반환되면 가상 기온을 숨기고 실제 예보·Open-Meteo 출처를 표시합니다.

범위를 벗어나거나 조회에 실패하면 가상 정보의 명확한 문구를 유지합니다. 가상 강수확률·날씨 상태 아이콘은 생성하지 않습니다. 실제 API가 반환한 경우에만 기간 내 일별 강수확률의 최댓값을 표시합니다. 데모 출발일도 실제 예약 날짜로 취급하지 않습니다.

실제 예보 우선과 실패 시 가상 표시의 브라우저 검증은 모의 API 응답으로 수행했습니다. 외부 Open-Meteo의 실시간 가용성을 새로 검증했다고 주장하지 않습니다.

## 5. 필요한 후속 데이터와 미구현 범위

확인 식사 횟수/출처, 실제 출발일, 방문 도시가 확보되면 실제 정보를 우선 표시합니다. 데모 수치는 prisma/presentation-demo.json에서 상품 ID별 수정·제거할 수 있습니다.

일본 외 실제 상품·도시 공급자는 아직 추가하지 않았습니다. AI 자동 거리 분석·지도 거리 계산·실제 예약·결제·공식 제휴는 미구현입니다. 추천 점수에는 식사와 신규 카드 예보를 추가하지 않았습니다.

## 6. 검증

원본/공개용 타입 검사와 프로덕션 빌드 통과. 단위 테스트 29개, 전체 브라우저 테스트 18개 통과.
기존 4단계 조건 입력, 필터·정렬·추천, 2/3개 비교, 상세·부모님 공유, 가상 예약, 관리자 CRUD/JSON/CSV 기능 유지.
모바일 8개 화면 WCAG 검사 오류 0, 일반/24px 큰 글씨 가로 넘침 없음. 실제 예보 우선/조회 실패 테스트용 상품은 검증 후 삭제했습니다.
추천 코드와 기존 seed-data.json은 변경 전 Git 버전과 완전히 동일함을 확인했습니다.
